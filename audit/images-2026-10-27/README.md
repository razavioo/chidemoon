# Image review and optimization

Full-library rollout completed and verified 2026-10-28: all 4,602 JPEG/PNG/WebP attachments (~1,020.43 MiB originals), including all published product galleries, have 12,588 responsive WebP derivatives (320/640/960/up to 1440px, no upscale). All 4,446 published product image references are covered. Final verifier: zero missing media images, zero missing product images, zero invalid derivative files. Original files remain intact for zoom and rollback. SVG/vector assets retain their native format.

Corrected sizes for hero/banner, product and article cards, route graphics, article covers, product gallery. Hero eager/high-priority, derivatives preserve aspect ratio. Product cards and main gallery now contain instead of cover to avoid cutting off products. Hero and article full image ratio preserved. Existing Look picture/WebP sources preserved to avoid shifting hotspots. Category landing currently has text navigation and no image cards; term-image handling is supported if images are added.

Measured file payload examples: hero 280,694 -> 29,178 bytes (90% reduction); article card 99,506 -> 34,022 bytes (66%). These are file-byte comparisons, not measured whole-page speed/Core Web Vitals improvements. Optimized-set originals 186.58 MiB vs one <=640px derivative per asset 26.42 MiB (different resolutions, not total disk savings). New derivatives consume additional disk.

Visual QA: desktop/mobile home, product, article; Looks reviewed for natural aspect ratios. Mobile no document overflow. Real page confirms product cards choose 320px WebP at ~206px display and mobile hero 640px at358px. Six read-only integration checks pass: compact/legacy storage compatibility, responsive candidates, sizes retained, original zoom links retained, external images unchanged, intrinsic ratio retained. PHP lint and git whitespace checks pass. Small imported copies of the identical photo resolve to known larger same-source images where available; no invented detail/upscaling.

Limit: did not individually visually inspect all 4,602 images. Some original low-resolution assets require a better source image. Conversion is repeatable using tools/optimize-important-images.php apply 0 10000 all-media. Derivatives are served through the chidemoon_responsive_images_v1 manifest. Version 2 stores metadata once per attachment and maps upload paths to IDs, avoiding the MySQL packet limit encountered with duplicated size aliases. Two undecodable imported WebP copies were converted from the identical, sufficiently large PNG originals with matching aspect ratios. Source records and original files are preserved. See all-media-optimized.json and verification-final.json for full output.
